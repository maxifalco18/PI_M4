Fase 3: Plan de Implementación (Work Breakdown Structure) - Proyecto Integrador M4
Como tu líder técnico, he desglosado el proyecto en 5 Hitos Secuenciales (Milestones). Este orden no es arbitrario; está diseñado para probar el sistema desde los cimientos hasta el techo, asegurando integraciones tempranas ("Shift-Left Integration").
HITO 1: Cimientos de Infraestructura (AWS Cloud)
El objetivo aquí es preparar la "tierra" antes de construir la casa. Todo se basa en la seguridad y el almacenamiento.
* Tarea 1.1 - Aprovisionamiento S3: Crear el bucket pi-henry-datalake-[tu-apellido] con las subcarpetas /raw, /silver y /gold.
* Tarea 1.2 - Gestión de Identidades (IAM): Crear un Rol IAM para la instancia EC2 que permita lectura/escritura exclusiva a este bucket S3 (Least Privilege). Cero llaves estáticas.
* Tarea 1.3 - Lake Formation (Opcional/Recomendado): Registrar el bucket S3 en Lake Formation para futuras consultas seguras con Amazon Athena.
* Dependencias: Ninguna.
HITO 2: Motor de Orquestación y CI/CD
Instalamos el "cerebro" (Airflow) y automatizamos su actualización (GitHub Actions).
* Tarea 2.1 - EC2 Setup: Levantar instancia t2.micro (Ubuntu). Asignar el Rol IAM creado en Tarea 1.2. Configurar Security Group (Abrir puertos 22 para SSH y 8080 para Airflow UI a tu IP).
* Tarea 2.2 - Despliegue de Airflow: Instalar Docker y Docker Compose. Desplegar Airflow usando la imagen oficial (docker-compose.yaml optimizado para bajos recursos).
* Tarea 2.3 - Automatización CI/CD: Configurar un workflow en GitHub Actions. Cada vez que hagas push a la rama main, la Action copiará los DAGs automáticamente a la carpeta dags/ de la EC2 vía SCP/SSH.
* Dependencias: Hito 1 completado.
________________
HITO 3: Ingesta Batch (Airbyte)
Conectamos las tuberías de las fuentes históricas hacia la capa Raw.
* Tarea 3.1 - Conexión PostgreSQL: En Airbyte Cloud (Free), configurar el conector origen hacia la BD PostgreSQL provista en el proyecto. Configurar destino al bucket S3 (Capa /raw/postgres/).
* Tarea 3.2 - Conexión API: Configurar el conector origen HTTP genérico apuntando a los JSON de clima/geografía. Destino: S3 (Capa /raw/api/).
* Tarea 3.3 - Integración Airflow: Crear el archivo ingest_dag.py en Airflow utilizando el AirbyteTriggerSyncOperator para disparar estas extracciones diariamente.
* Dependencias: Hitos 1 y 2.
HITO 4: Transformación Distribuida (PySpark & Medallion)
El "trabajo pesado". Procesamos datos de Raw a Silver, y de Silver a Gold.
* Tarea 4.1 - Script Silver (Limpieza): Escribir raw_to_silver.py. Leer JSON/Parquet de /raw, aplicar schema enforcement, castear tipos de datos, aplanar JSON y escribir en /silver (formato Parquet).
* Tarea 4.2 - Script Gold (Lógica de Negocio): Escribir silver_to_gold.py. Leer de /silver, hacer JOIN entre datos de Postgres y API, agregar datos para responder a las preguntas de negocio y guardar como One Big Table (OBT) particionada en /gold.
* Tarea 4.3 - Delegación del Cómputo (Databricks/EMR): Configurar el entorno externo de Spark (Databricks Community) montando el S3 o usando credenciales temporales.
* Tarea 4.4 - Orquestación Spark: Actualizar el DAG de Airflow para que, tras el éxito de Airbyte, dispare los scripts de Spark remotamente (usando APIs de Databricks o Livy).
* Dependencias: Hito 3.
HITO 5: Streaming Pipeline (Kafka & Spark Lambda)
La fase más avanzada: integrar eventos en tiempo real sin romper el histórico.
* Tarea 5.1 - Aprovisionamiento Kafka: Configurar un clúster o contenedor de Kafka para los tópicos de eventos (ej. live_events).
* Tarea 5.2 - Spark Structured Streaming: Escribir streaming_to_gold.py. Suscribirse al tópico de Kafka, aplicar validaciones en micro-batches (con Watermarking) y hacer "append" a la capa Gold o Silver.
* Tarea 5.3 - Consolidación Lambda: Validar que la capa Gold contenga datos consistentes tanto del flujo Batch (Postgres/API) como del Streaming.
* Dependencias: Hito 4.
________________
⚠️ RIESGOS TÉCNICOS CRÍTICOS (Atención)
1. Riesgo OOM (Out Of Memory) por Kafka: El Hito 5 es sumamente peligroso para el AWS Free Tier. Si intentas correr Airflow (Docker) Y Kafka (Zookeeper/Broker) en la misma instancia t2.micro, la RAM colapsará al 100% y la máquina se colgará irremediablemente.
   * Mitigación Mandatoria: Debes usar un servicio de Kafka administrado gratuito (como Confluent Cloud Free Tier o Upstash) o, en su defecto, correr Kafka en tu máquina local y simular el streaming hacia la nube. ¡NO instales Kafka en la EC2 t2.micro que orquesta Airflow!
2. Dependencias del DAG: Si Airflow lanza Spark antes de que Airbyte termine, procesarás datos vacíos. Usaremos Sensors o dependencias estrictas (>>) en Airflow para asegurar el orden.
